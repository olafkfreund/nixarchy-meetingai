# Intent: a UI that is easy to use and looks native to Omarchy

## Problem

The owner, Codex and the session model reviewed the overlay against the
Omarchy plugin docs (`plugins.omarchy.org/develop.html`, the shell
reference, `shell-dev.md`, `theming.md`) and screenshots of every mode.
The core works, but it is not yet easy to use or polished:

- **Alignment (owner):** text fields, dropdowns and buttons in the same
  row have different heights and baselines (Candidate tab: dropdown,
  name field and "New"; path field and "Attach"; Team callout: "Done" is
  taller than "Discussed"). Each row sizes itself by hand instead of using
  Omarchy's `controlHeight` token (`Commons/Style.qml:251`).
- **Candidate tab (owner):** cramped and hard to read. The competency
  field clips "Technical depth", source quotes are squeezed under each
  question, fonts mix monospace and proportional, and there is no spacing
  rhythm between sections.
- **Keyboard:** most buttons can't be reached with Tab. `IconButton`
  inherits `Ui.Button`, whose `focusable` defaults to false
  (`Ui/Button.qml:32`). Suggestion rows are mouse-only.
- **Destructive actions:** deleting a session or profile is one click
  with no confirmation (`Library.qml:158`, `:230`), while the candidate
  delete has a two-click guard. Omarchy ships `Ui/ConfirmDialog.qml`.
- **First run and errors:** with no daemon, no provider or no model, the
  overlay shows one small error line. Failures land in the transcript
  instead of where the action was taken.
- **Hierarchy:** the live answer looks like every other card; an empty
  transcript takes most of the card in Interviewer mode; "Interview"
  next to "Interviewer" is confusing, and the four-button mode control
  is too wide at the 520 px minimum and at 150 % text.
- **Shell contract:** the outer card and consent callout use plain
  bordered rectangles where the shell reference asks for `BorderSurface`;
  the mode control could use `Ui/ButtonGroup.qml`. No `Accessible.name` or
  `Accessible.role` anywhere.
- **Robustness:** a daemon disconnect can throw in `Client.qml` (a `null`
  callback is called); a reconnect can leave a stale answer or duplicate
  history on screen.
- **Maintainability:** `Overlay.qml` is 917 lines and mixes transport
  state, geometry, transcript, answer card and three mode panels.

## Proposed outcome

- Every control in a row shares one height and baseline from the shell's
  control token, scaled with the text-size setting; a screenshot check at
  100 % and 150 % shows no clipping or spill-over in any tab.
- The Candidate tab is laid out for reading: one question per card with
  the source quote on its own line, competency as a quiet tag, actions
  aligned, comfortable spacing, consistent fonts.
- Everything is reachable and usable from the keyboard, with visible
  focus, screen-reader names, and Escape behaving predictably.
- Every destructive action asks for confirmation with Omarchy's dialog.
- First run shows one clear next step (start the daemon, pick a provider,
  pick a model); errors appear where they happened.
- The live answer is the strongest thing on screen; empty states are
  short; the mode control is compact and self-explaining.
- The overlay follows the shell's shared surfaces and components, and the
  QML is split by responsibility so it stays easy to change.

## Affected users and systems

- The owner, in every mode.
- `shell/**` only (QML, the fake daemon and the screenshot harness). No
  daemon protocol change is expected beyond, at most, fields the UI needs
  for first-run readiness.

## Constraints

- Monochrome glyphs only; follow the live Omarchy theme, including light
  themes; keep the existing spacing, radius and text-scale settings.
- Use Omarchy's shared `Ui` components and `Style`/`Color` tokens before
  writing custom ones.
- No regressions in the team and interviewer flows; lint, smoke tests,
  contrast check and screenshots must pass.
- The screenshot harness draws on the real desktop: crops are checked
  before they are shared, and other windows that cover the overlay are
  discarded.

## Open questions

1. **Mode names:** rename the modes to make the difference clear, for
   example *Assist · Interview me · Team · Interview someone*? (Proposed:
   yes, with a one-line description under each in a compact picker.)
2. **Fonts:** use one proportional UI font for everything except code,
   instead of the current monospace labels and inputs? (Proposed: follow
   what first-party Omarchy panels do.)
3. **Order:** do this before the call-detection work, so the new
   "Take notes?" prompt is built on the new components? (Proposed: yes.)
