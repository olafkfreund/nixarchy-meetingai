# Intent: MCP server so LLMs and AI agents can control nixarchy-meetingai

## Problem

The app can only be driven by a person, through the Quickshell overlay, or
by a script, through `nixarchy-meetingai ctl` and raw JSON. An LLM or AI
agent (Claude Code, Codex, agy, or the owner's own agents on the agent bus)
has no standard, typed way to:
- start or stop note-taking
- read the live transcript
- ask a question in context
- get the suggestions and the meeting notes
- look up past meetings

## Proposed outcome

`nixarchy-meetingai mcp` runs an MCP server over stdio that any MCP client
can add. It exposes typed tools and resources built on the daemon's
existing socket API; no new daemon logic beyond what the tools need.

- **Read tools:** status, live transcript (from a time or line), current
  answer and suggestions, list and search meetings, a meeting's notes and
  transcript.
- **Act tools:** ask a question (returns the streamed answer when done),
  start, stop and restore a session, regenerate notes, set non-secret
  settings (mode, pace, provider, model).
- **Resources:** `meeting://current/transcript` and
  `meeting://<id>/notes`, so clients can subscribe to or attach them.
- The Home Manager module can register it with the user's MCP clients.

## Affected users and systems

The owner's agents and MCP clients on this machine; the daemon's socket
protocol (read only, plus existing commands); `src/` (a new `mcp` module
and CLI subcommand); `nix/` (registration).

## Constraints

- **Local only:** stdio transport; it reaches the daemon only through the
  user's own `0700` socket.
- **Keys never leave the daemon:** no tool returns or sets API keys.
- **Consent:**
  - an agent must not start recording people unless the owner allows it,
    so `record.start` over MCP is off by default (setting
    `mcp_allow_record`)
  - the overlay shows when an agent started or stopped recording
- **Transcripts are sensitive:** reading them is allowed, because the
  owner's agents are trusted local clients, but every MCP call is logged
  to the daemon log.
- **No new dependencies,** if a small hand-written JSON-RPC stdio loop is
  enough; evaluate the official `rmcp` crate in the spec.

## Open questions

1. Should agents be allowed to start recording at all, or only read and ask?
   (Proposed: off by default, one setting turns it on.)
2. Which MCP clients should the Home Manager module register it with
   automatically (Claude Code, Codex, agy)?
3. Should the server also push live transcript updates to clients that
   support notifications, or is polling with "transcript since line N"
   enough? (Proposed: polling first.)
