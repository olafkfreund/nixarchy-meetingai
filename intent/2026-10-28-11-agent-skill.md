# Intent: a skill so Claude, Codex and agy can answer questions about meetings

## Problem

Meeting notes, transcripts and action items live only in the app's
encrypted database. To read them outside the overlay you need to know the
`nixarchy-meetingai ctl` commands and meeting ids, or register the MCP
server separately in each tool. Asking an agent "show me the latest
meeting notes" or "what did we agree with Jim?" does not work today.

## Proposed outcome

In Claude Code, Codex or agy, the owner can ask in plain words and get an
answer from their own meetings:

- the notes (recap) of the latest meeting, or of one picked by title/date
- a list of recent meetings
- open action items, per meeting or for a recurring series, and "last time"
- the transcript of a meeting, or what is being said in the current one
- (if approved below) a search across all past meetings for a topic

The skill is installed for all three tools by the Home Manager module, so
it appears with `programs.nixarchy-meetingai.enable` and needs no manual
setup.

## Affected users and systems

- This repo: a new `skills/meetingai/SKILL.md`, the HM module
  (`nix/hm-module.nix`), README.
- p620 home directory: `~/.claude/skills/`, `~/.agents/skills/` (Codex),
  `~/.gemini/antigravity/skills/` (agy), the way the owner's other skills
  are installed.

## Constraints

- Read-only: the skill never starts or stops recording, deletes, or
  changes settings. It uses the existing `ctl` read commands.
- No new network exposure: it talks to the local daemon socket only.
- Whatever an agent reads goes to that agent's provider; the skill says
  so, and local-only interviews stay invisible (the daemon already hides
  them).
- Does not collide with the #3 rewrite branches (no `src/db` edits).

## Open questions

1. **Search across meetings:** the daemon can search notes and
   transcripts in the database, but `ctl` does not expose it (only titles
   are listed). Add one read-only `meetings.search` socket command so
   "what did we decide about X" works? Recommended yes (small).
2. **Install by default** when the module is enabled, with an option to
   turn it off (`skills.enable`, default true)? Recommended yes.

## Answers (owner approved the intent with the recommendations, 2026-10-28)

1. Yes: add a read-only `meetings.search` command.
2. Yes: installed by default, `skills.enable` to turn it off.
