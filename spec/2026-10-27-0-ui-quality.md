# Spec: a UI that is easy to use and looks native to Omarchy

## Decisions on the intent's open questions (the owner approved the proposals)

1. **Mode names:** *Assist · Interview me · Team · Interview someone*,
   shown in a compact picker with a one-line description each. Setting
   values stay `general | interview | team_meeting | interviewer`, so
   nothing stored or sent over MCP changes.
2. **Fonts:** follow first-party panels: one family, `Style.font.family`
   (Omarchy's system monospace, e.g. JetBrainsMono Nerd Font), for every
   label, input, bubble and answer. Sizes only from `Style.font.*` × the
   text-scale setting. Markdown code blocks keep the same family.
3. **Order:** this work lands before call detection.

## Design

### 1. One control metric (owner's alignment requirement)

- `shell/Theme.qml` (new, ~30 lines, a singleton inside the plugin):
  - `ctl = Math.round(Style.spacing.controlHeight × ts)`, the one height
    for every TextField, Dropdown, Button, ToggleSwitch row and
    IconButton in a form row
  - `gap = Style.spacing.controlGap × ts`, `padX`, `padY`, `radius`,
    `section` (space between groups) and the font sizes
  - Overlay, Library and Composer read these instead of their own
    `root.padX`/`gap` copies and hand-set heights
- **Rows:** every form row is a `RowLayout` with
  `Layout.preferredHeight: Theme.ctl` and
  `Layout.alignment: Qt.AlignVCenter` on each child. Fields take
  `Layout.fillWidth`; buttons get the same height and a minimum width.
  No fixed pixel widths that can clip text; widths come from
  `implicitWidth` or `fillWidth`.
- **IconButton** with or without an icon has the same height (the
  callout's "Done" is no longer taller).
- **Shared components:** `Ui.TextField`, `Ui.Dropdown`, `Ui.Button`,
  `Ui.ToggleSwitch` stay. Our wrappers only set the size and
  `focusable: true`.

### 2. Candidate tab, laid out for reading (owner's report)

- **Sections** with `Ui.PanelSectionHeader`: *Candidate*, *Documents*,
  *Question bank*, *Danger zone*. `Theme.section` spacing between them.
- **Candidate row:** picker (fills), then "New…", which opens an inline
  name field + Create/Cancel row. No more two empty fields side by side.
- **Documents:** one row per attached file (kind tag, name, size). One
  "Attach CV…" and one "Attach job description…" button, each opening a
  path row only when clicked.
- **Question cards:** each question is a card with, top to bottom:
  - the question text (editable, wraps, full width)
  - the source quote on its own line, wrapped, muted, never clipped
  - a footer row: the competency as a quiet tag (wraps, never clipped),
    then up / down / delete aligned right
- **Generate:** a primary button with a progress state ("Generating…")
  and the "N dropped" note under it.
- **Danger zone:** "Delete candidate data…" opens `Ui.ConfirmDialog`
  naming what goes (CV, job description, questions, the interview
  recording, notes and chat). It replaces the two-click guard.
- **Read-only** past candidates show a single banner line explaining why.

### 3. Keyboard and accessibility

- Every IconButton and Library button sets `focusable: true`; the overlay
  focuses the composer when it opens (as `plugins/emojis/Emojis.qml`
  does).
- Suggestion rows become focusable buttons (Enter sends); number keys
  1/2/3 keep working.
- The mode picker is `Ui.ButtonGroup`, which is keyboard-navigable.
- Escape order: close an open dialog or drawer, then cancel an edit, then
  close the overlay.
- `Accessible.name` and `Accessible.role` on every control, including the
  record button ("Start recording" / "Stop recording, 12 minutes"), mic,
  speaker and settings.

### 4. Destructive actions

`Ui.ConfirmDialog` for: delete session, delete profile, delete
candidate, quit daemon (the bar menu's "Quit" becomes "Stop Meeting AI…"
and says a recording will be finished first).

### 5. First run, loading and errors

- **Setup card** in the answer area when something is missing, with one
  next step each:
  - daemon not running → "Start the service" (runs `systemctl --user
    start nixarchy-meetingai`) and the command to copy
  - no usable provider → "Choose a provider" (opens Providers)
  - whisper server down → the exact `systemctl` unit to check
- The daemon's `state` gains `ready: {daemon, chat, speech}` booleans and
  a `hint` string per missing part (computed from `chat_config` and
  `speech_config`); the UI only renders them.
- **Errors where they happen:** a failed answer shows inside the NOW card
  with "Retry"; a failed Library action shows under that section; the
  header error line stays only for connection loss.
- **Waiting state:** "Writing…" with a subtle animated bar in the NOW card
  between `answer.started` and the first delta.

### 6. Hierarchy and layout

- **The NOW answer** gets the largest body size (`Style.font.body × 1.15 ×
  ts`), a solid accent rule, and metadata (provider, model) in caption
  size on one quiet line.
- **Transcript bubbles** step down: smaller text, less fill; archived
  answers collapse to two lines with "Show".
- **Empty transcript** collapses to one line ("Listening for speech…" or
  "Press record to start"), so the mode panel and NOW move up.
- **Interviewer empty bank** shows "Prepare candidate" (opens the
  Candidate tab) instead of pointing at Settings.
- **Header:** the mode picker shows the current mode's short name, and
  opens a small list with descriptions. It fits 520 px at 150 %.

### 7. Shell contract and robustness

- The outer card and the consent callout use `Ui.BorderSurface` with the
  theme's border spec.
- `Client.qml`: on disconnect, only function callbacks are called (null
  entries are skipped), and session state (`now`, transcript, items,
  candidate) is cleared. On reconnect, `history` replaces the transcript
  instead of appending to it.

### 8. Structure

`Overlay.qml` (917 lines) is split by responsibility, with no behaviour
change in the move:
- `Header.qml`: record, timer, levels, mode picker, settings
- `Transcript.qml`
- `NowCard.qml`
- `ItemsPanel.qml`
- `QuestionBankPanel.qml`
- `ConsentBanner.qml`
- `SetupCard.qml`

`Overlay.qml` keeps the window, geometry and layout.

## Alternatives rejected

- **A proportional UI font:** first-party panels use one system family;
  mixing ours made the screenshots look inconsistent.
- **Our own form components:** Omarchy already ships aligned, themed
  `TextField`/`Dropdown`/`Button`. The misalignment comes from how we
  size them, not from the components.
- **Keeping the two-click delete:** inconsistent with the rest, and
  ConfirmDialog states what will be lost.
- **A QML test framework for interaction:** too heavy for this; the
  screenshot harness plus fake-daemon scenarios cover the states, and
  keyboard paths get a smoke script.

## Risks

- **Monospace answers are wider:** long answers wrap more. Mitigation: the
  NOW card gets the space the empty transcript used to take.
- **ButtonGroup width:** if four names don't fit, the compact picker is
  the fallback (decided above).
- **Splitting Overlay.qml** can break bindings: split first with no other
  change, verify, then restyle.
- **The screenshot harness** draws on the real desktop. Crops are checked
  before use, and covered crops are retaken.

## Verification

- **Alignment check:** a small script reads the crops and verifies that in
  each form row the control boxes share top and bottom edges (±1 px),
  using the harness's recorded geometry
  (`shell/tests/geometry.js` dumps the `x/y/height` of every control with
  `objectName` to the fake log). It runs at 100 % and 150 %, in every
  scenario.
- **No clipping:** for every `Text` with `elide: Text.ElideNone` inside a
  form, `implicitWidth <= width`, checked by the same geometry dump.
- **Screenshots:** live, k8s, team, interviewer and r5, plus a new
  `first-run` scenario (no daemon / no provider), at 100 % and 150 %.
  Owner sign-off on the crops.
- **Keyboard smoke:** a scripted run that tabs through the header and the
  Candidate tab and asserts focus moves (`activeFocusItem.objectName`
  logged).
- **Unchanged checks:** lint, smoke, smoke-real, contrast, the full cargo
  suite (for the `ready` state), and `nix flake check`.
- **Reviews:** Opus, then Codex and agy, read-only.
