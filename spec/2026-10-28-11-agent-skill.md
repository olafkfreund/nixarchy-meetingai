# Spec: a meetings skill for Claude, Codex and agy

## Design

### The skill: `skills/meetingai/SKILL.md`

One Markdown file with frontmatter `name: meetingai` and a description
that triggers on "meeting notes", "last meeting", "action items",
"what did we agree", "transcript", "standup", "series". The body tells
the agent to use `nixarchy-meetingai ctl <command> '<json>'` (NDJSON
reply, `.data` holds the result; `jq` to read it) and nothing else:

| Ask | Command |
|---|---|
| recent meetings, newest first | `session.list`, keep `kind == "meeting"` |
| latest meeting's notes | first meeting from `session.list`, then `notes.get {"meeting": id}` |
| a meeting by topic or words said | `meetings.search {"query": "...", "limit": 10}` (new) |
| action items | `items.list {"meeting": id}` |
| recurring meetings, "last time" | `series.list`, `last_time.get {"series": id}` |
| transcript | `transcript.get {"meeting": id, "limit": 200}`, paging with `after_line` |
| the meeting happening now | `state.get`, `now.get`, `transcript.get {}` |

Rules in the skill: read-only (never `record.*`, `session.delete`,
`settings.set`, `items.update/delete`); if the daemon is not running,
say so and suggest `systemctl --user start nixarchy-meetingai`; quote
notes as written, summarise only when asked; one line noting that what
it reads goes to the agent's own provider.

### Daemon: two small read-only additions (`src/daemon/session.rs`, `src/daemon/protocol.rs`)

- `session.list`: meeting entries gain `started_at` (additive; the
  overlay ignores unknown fields), so "latest" and "yesterday's" work.
- `meetings.search {query, limit?}`: calls the existing
  `db::meetings::search` (titles, transcript lines and notes via
  `notes_fts`), returns `[{id, title, started_at}]`, limit default 10,
  clamped 1–50. Local-only interview meetings are filtered out the same
  way `session.list` does (`candidates::local_only_ids`). Empty query →
  error "query is empty".
- Neither touches `src/db/` (the #3 rewrite owns those files).

### Install: `nix/hm-module.nix`, `nix/package.nix`

- The package installs the skill to
  `share/nixarchy-meetingai/skills/meetingai/SKILL.md`.
- New option `programs.nixarchy-meetingai.skills.enable` (default
  `true`). When on, `home.file` links the directory to
  `.claude/skills/meetingai`, `.agents/skills/meetingai` (Codex reads
  it) and `.gemini/antigravity/skills/meetingai` (agy), the same places
  the owner's other skills live.
- README: a "Ask your agents" section; the generated options block
  updates.

## Alternatives rejected

- **MCP registration in each tool:** works, but needs a manual `mcp add`
  per tool and host, and the MCP tools cannot search notes either. The
  skill uses the same daemon commands with no setup. The MCP server
  stays for agents that prefer it.
- **A separate CLI command per question** (`nixarchy-meetingai notes
  --latest`): more code than the two daemon additions; the JSON `ctl`
  path already serves agents well.
- **Exporting notes to files for agents to grep:** puts decrypted notes
  on disk; out of scope (a possible later task).

## Risks

- A skill path already present (a hand-made `meetingai` skill) makes
  Home Manager refuse to link it; the activation error names the file.
  None exists on p620 today.
- Codex's skill directory: Codex reads `~/.agents/skills` on p620 (the
  owner's shared skills are there); if a Codex version reads only
  `~/.codex/skills`, the skill is missing for Codex. Verified during
  implementation by asking Codex to list its skills.
- Agents read notes into their providers' context: documented in the
  skill and README; local-only interviews stay hidden.

## Verification

- Unit tests in `session.rs`: `meetings.search` finds a meeting by a
  word only in its notes and one only in its transcript, hides a
  local-only interview, rejects an empty query, clamps the limit;
  `session.list` meeting entries carry `started_at`.
- `nix flake check` (HM eval with `skills.enable` on and off: the three
  `home.file` entries appear or not).
- On p620 after deploy: in Claude Code, Codex and agy, "show me the
  latest meeting notes" returns the latest recap; "search my meetings
  for <word>" finds it.
