# Plan: Noise does not become transcript lines

This plan **measures only**. It ends with a result and a stop. If the check wins, its code gets a separate plan.

**A change from the spec, for this approval:** the spec gives the replay tool a flag. Instead, a small separate tool applies the check offline to saved chunks, because that needs no change under `src/`, and it lets thresholds be tried without new Parakeet runs. It shows which lines a check would remove, not how the live path would run without decoding them. So **a win here is provisional:** the delay figure is a computed estimate, and the code plan must measure live, paced delay before anything ships.

## Decisions carried from the approved spec

- Compared: today's build, and a Silero voice-activity check on each finished chunk. Nothing else. No word lists, no neighbour rule, no setting.
- Sets: #73's noise and guard sets in `~/.cache/meetingai-eval/en73/{s1,s2}`, and a new set of real short utterances from AMI, split by meeting into a tuning half and a held-back half, used once.
- The owner decided no real-call recording is needed, and doing nothing is acceptable. The result states the limits.
- **The rule.** The check wins only if all of these hold on the held-back half and both noise samples, against today's build re-measured on the same sets:
  - invented lines on bursts fall at least 75% from each sample's own baseline, and room tone doesn't rise;
  - at least as many real utterances are kept, per utterance, with every newly lost one listed;
  - word errors within 0.5 points of the baseline, and no more bleed lines;
  - median and p95 delay per channel no worse than the spread between two baseline runs;
  - the check's own time, for every chunk including rejected ones, under 10 ms at the median.
- If it doesn't win, nothing changes, and #83 closes with the finding.

## Traps

- **The live path doesn't change in this plan.** No edits under `src/`. The check runs offline on saved chunks.
- Audio stays out of git (`tools/accuracy/data/` and the cache only).
- **No artificial CPU load on p620.** Check the agent bus and other sessions' CI before each long run, run one at a time, and stop if another session asks.
- Never `torch.load(weights_only=False)`. Downloaded data is untrusted: Python that reads it runs with `-I`.
- Before `cargo`: `find target/debug target/release -maxdepth 2 -name 'lib*.so*' ! -perm -u+w -delete`.
- Codex can't run `cargo` or `nix` in its sandbox. Claude runs the checks and commits. A moved `HEAD` fails its handoff, so don't commit in the worktree during one.
- Don't start quickshell. No wildcards under `/tmp`.

## Steps

### 1. Builder (coder) — `tools/accuracy/short_replies.py`, `tools/accuracy/selfcheck.py`, `tools/accuracy/README.md`

Reads `~/.cache/meetingai-eval/ami-hf-ihm/raw/*.parquet` (columns `meeting_id`, `audio_id`, `text`, `audio`, `begin_time`, `end_time`, `speaker_id`) using `nix-shell -p 'python3.withPackages(p:[p.pyarrow])'`, as other AMI tools did.

- Select `text` with at most 3 words and `end_time - begin_time` at most 1.5 s. Keep the reference as written. Drop anything with no letters.
- Split by `meeting_id` with a fixed seed: half tuning, half held back. No meeting is in both.
- Cap each half at 400, chosen by the same seed, so a run stays under 30 minutes at `--speed 8`.
- Write `short/{tune,held}/set.wav`, 16 kHz stereo, with the utterances on channel 1 (remote), each followed by 3 s of silence. Channel 0 is silent. Also `set.json`, listing each utterance's window and reference, under `~/.cache/meetingai-eval/en83/`.
- A `--count LINES.jsonl` mode assigns each line to the one utterance whose window it overlaps most, so a line can't count twice, and marks that utterance kept if the line has a word. It prints the ids, and how many lines share a word with the reference. Comparing a baseline with a checked run gives the **lost** list: utterances the baseline had a line for and the check removed. The check only removes lines, so an unrelated word in the baseline can't make it look better. The score for the rule is this lost list.

Self-check, in `selfcheck.py`, without the real cache: asserts the limits, that no meeting is in both halves, that the same seed gives the same choice, and the `--count` result on a small made-up run, including a line outside any window, a line spanning two windows, and the lost list between two runs.

Check: `python3 -I tools/accuracy/selfcheck.py`.

### 2. Offline check (codex) — `examples/vad_gate.rs`

`vad_gate RUN.jsonl FILE.wav --model silero_vad.onnx --threshold T --min-speech S`. `RUN.jsonl` is `accuracy_replay --no-filter` output (`chunk` and `line` records, `examples/accuracy_replay.rs:145`, `:522`, `:534`).

- For each `chunk`, take its samples from the WAV by `channel`, `start` and `end`, and run sherpa-onnx's `VoiceActivityDetector` (`sherpa-onnx-2.0.1/src/vad.rs`, `SileroVadModelConfig`) from a clean state. A chunk passes if it finds at least `S` seconds of speech.
- Print the same records, without the `line` of a chunk that doesn't pass. The `chunk` record stays, because live the chunker runs before the check, so `LineFilter` would still see that channel's activity. `accuracy_replay --filter-lines` then runs on what's left.
- Time each chunk's check, including rejected ones. Print a `{"kind":"gate","channel","start","ms","passed"}` record per chunk, and a summary with the median and p95, to stderr.
- It's an example, so it needs no change under `src/`. It uses the `sherpa-onnx` dependency the crate already has. Test the pure part (taking a chunk's samples, a line without its chunk, an invalid record) in the example's own tests.

The model comes from the fetch in `nix/silero-vad.nix` at `2620fc6^` (URL and hash there). Download once to `~/.cache/meetingai-eval/en83/`, checking that hash.

Check: `nix develop -c bash -c 'cargo test --workspace && cargo clippy --workspace --all-targets -- -D warnings && cargo fmt --all -- --check'`

### 3. Measure (Claude)

Using `--engine parakeet`, at natural load, one run at a time:

1. **Chunks, once:** `accuracy_replay --no-filter`, which records chunks and lines but no delay, on bursts, room tone, silence, `double_talk`, `remote_only` and `libri` for samples 1 and 2, and on both short sets, at `--speed 8` as #70 did, and bursts at 1x first to confirm speed doesn't change the count. `--filter-lines` then gives the baseline's released lines, scored with `tools/accuracy/score.py` where it has a reference. Compare sample 1 with #73's numbers, and find out why before going on if they differ. The short sets are scored only with `--count`, since `score.py` needs a reference file they don't have.
2. **Delay, twice:** normal paced runs at 1x on `double_talk` and `remote_only`, sample 1, which record `released_at`. The two runs give the median and p95 per channel, and the spread.
3. **Tune on `short/tune` and the bursts of sample 1 only:** thresholds 0.2, 0.3, 0.5 and minimum speech 0.05, 0.1, 0.2 s, offline with `vad_gate`, so with no new Parakeet runs. Pick the setting that loses the fewest utterances while reaching the noise target. If none reaches it with no utterance lost on the tuning half, the result is already "no", and step 3.4 is skipped.
4. **Once, with the setting fixed:** `short/held`, both samples' noise sets, and the guards, offline.

**Delay against the rule:** for each line in the paced runs that the check keeps, its delay plus that chunk's check time, then the median and p95 per channel, compared with the spread. Timing comes from a `vad_gate` pass on the paced run's audio. This is an estimate. It doesn't count the Parakeet time a dropped chunk frees, so it errs against the check, and it doesn't replace the live measurement a code plan must do.

### 4. Result (Claude) — `docs/eval/2026-11-noise-lines.md`

The sets, each number against the rule, the setting chosen, every lost utterance's reference, the limits (built sets, AMI isn't the owner's calls, noise during a conversation not measured, the delay is a computed estimate), and the decision.
