# Plan: only the owner's voice is labelled as the owner

## Approved decisions (copied from the spec, with the owner's sweep order)

- **Model:** `3dspeaker_speech_campplus_sv_zh_en_16k-common_advanced.onnx`
  (26 MB, 16 kHz, Apache-2.0) from the sherpa-onnx
  `speaker-recongition-models` release, fetched by `nix/speaker-model.nix`
  with a fixed hash; its path reaches the daemon through the Home Manager
  module's environment. Used through
  `sherpa_onnx::SpeakerEmbeddingExtractor`, loaded lazily on the first
  check, never without a sample. The app never downloads it.
- **Sample:** socket commands `voice.enroll` (12 s from the current mic
  while no meeting records; needs 8 s of speech, else stores nothing and
  says why), `voice.status` (`{enrolled, model, created, paused}`, never
  the vector), `voice.delete`. All three refused for `--agent` and MCP
  origins. Stored: averaged normalised embedding, model file name, time, in
  a one-row table `voice_sample` in the encrypted DB. Audio stays in
  memory during enrollment only. A sample from another model file counts
  as absent.
- **Check:** for every final mic line (either engine), cut `[start, end]`
  from a 30 s ring of 16 kHz mic samples, embed on a blocking thread,
  cosine against the sample. Under 1.5 s of speech, or between the two
  thresholds: stays the owner's. Under the low threshold: `room`. The line
  is shown at once as the owner's and relabelled when the check says
  `room`.
- **Room:** DB `who` value `room`; overlay label "Room" in the "Them"
  style; recaps, notes and live answers say "Someone in the room", never
  the owner, and give it none of the owner's action items.
- **Setting:** `voice_check_paused` (bool, false). Overlay: state, "Record
  my voice", "Record again", "Delete".
- **Merge bar:** on the owner's recordings, at most 1 in 50 owner lines
  labelled `room`.
- **Order (owner, 2026-10-29: "do them in one sweep"):** built now, in
  parallel with #32. The ring is fed from the daemon's audio hook in
  `src/daemon/session.rs` (where `tap_audio` already receives the
  interleaved mic+system frames after mute), so the rewrite #3 step 10
  files are not edited and the intent's reason for waiting (the clean-room
  step re-doing new code) does not arise. This replaces spec sections 3
  (ring "in listen.rs") and 5.

## Steps

1. **Model in Nix** (`nix/speaker-model.nix` new; `nix/hm-module.nix`:
   env var with its path; `flake.nix`: a `voice-check` flake check like
   `parakeet-decode` that runs step 2's real-model test).
   → verify: `nix build` of the model; `nix flake check`.
2. **`src/speech/voice_check.rs`** (new; `src/speech/mod.rs` exports it):
   `MicRing` (fixed capacity, absolute sample index, cut by seconds across
   the wrap, mic taken from interleaved frames), `embed(&[f32]) ->
   Option<Vec<f32>>` behind a seam, `cosine`, `Verdict { Owner, Room }`
   with "too short or unclear stays Owner", enrollment averaging over
   1.5 s windows with a speech-level gate. Threshold constants marked
   provisional until step 7.
   → verify: unit tests (wrap, short span, unclear, room, averaging,
   too little speech); a `#[ignore]` real-model test run by the flake check.
3. **DB and setting** (`src/db/schema/schema.sql`: `voice_sample`;
   `src/db/repos/voice.rs` new: save, load, delete; `src/core/models/settings.rs`:
   `voice_check_paused`).
   → verify: repo round-trip tests; settings default test.
4. **Daemon** (`src/daemon/session.rs`): ring fed beside `tap_audio`;
   `voice.enroll`/`voice.status`/`voice.delete` with origin refusal; the
   per-line check off the audio thread; relabel event to the overlay;
   stored `who = "room"`.
   → verify: daemon tests with a fake embedder: room relabel, paused,
   no sample, agent refused, vector never in replies or events.
5. **Recaps and prompts** (`src/ai/recap.rs` and the prompt builders that
   read `who`): `room` as "Someone in the room", no owner action items.
   → verify: unit tests on recap and prompt text.
6. **Overlay** (`shell/Transcript.qml`, `shell/Client.qml`, the settings
   view; `shell/tests/fake-daemon.py` for the new commands and event).
   → verify: `bash shell/tests/ci.sh` headless.
7. **Thresholds** (lead, p620, with the owner): enroll; score #32's
   recordings with the check off and on; set the thresholds in step 2's
   constants with the evidence in a comment; meet the merge bar.
8. **Ship:** PR linking intent, spec, plan; CI green; merge commit. Deploy
   to p620 from committed main, announced on the agent bus, not while
   recording; `voice.status` works, a short test shows a Room line from
   the phone.

## Deviations

- Step 1: a Home Manager option `speakerModel` (package, defaults to the
  pinned CAM++ derivation) carries the model, and the README's generated
  options block is refreshed (the docs-match check requires it). The
  variable is `MEETINGAI_SPEAKER_MODEL`, always set: the model is loaded
  only once a voice sample exists. The model file is 28.3 MB (the spec
  said 26 MB).
- Step 1/2: the real-model test lives in `tests/voice_model.rs` (skips
  without `MEETINGAI_SPEAKER_MODEL`) and the `voice-check` flake check runs
  `--test voice_model`: a `--lib` run needs fixtures the package source
  leaves out, the same reason `parakeet-decode` is an integration test.
- Step 5 (agy): the lead restored the original owner-grounding rule
  (a remote "can you ..." still gives the user the item) and kept only the
  room-label exclusion.
- Step 6 (agy): the text to read is longer than the spec's sentence, so a
  normal reading gives the 8 s of speech enrollment needs.
- Step 4: the stored model name is the model file name, which includes the
  Nix store hash, so a copied or rebuilt model file counts as absent (the
  sample must be recorded again).
- Step 4: a failed model load turns the check off until the daemon restarts
  and shows one error.
- Step 4: enrollment is also refused while dictating or with capture off,
  and `record.start` and `dictate.start` are refused while enrolling (the
  flag is set and checked under the daemon lock).
- Step 4: `meetings::label` was made `pub`.
- Step 6: the `shell/tests/ci.sh` contrast stage falls back to the default
  theme tree like the other scripts (commit ee6b5ce).
- Review fixes: the model file name is fixed at start and the embedder
  loads under its own lock that only check threads take, so the audio path
  never waits on the load; voice checks are counted and rolling notes and
  `finish_meeting_artifacts` (also `notes.regenerate`) wait for them, up to
  10 s, before reading lines; a relabel updates the stored row by the id
  `add_line` returned, the screen only when that meeting is the displayed
  one, and `transcript.relabel` carries `meeting` (the overlay ignores
  another meeting's); the mic ring is cleared when a recording finishes;
  `candidates::said` counts `room` lines with `them`, so a candidate next
  to the mic is not dropped. The model is 28 MB in the module description
  and README.
- Step 7 (owner, 2026-10-30: "drive it all", chose the public-dataset
  option): no owner recording. Thresholds are set on LibriSpeech
  test-clean (CC BY 4.0, 40 speakers): each speaker in turn is the owner
  (12 s enrollment from their own utterances), every other speaker is the
  room, clean and with far-end bleed mixed into the mic. The merge bar
  (at most 1 in 50 owner lines labelled `room`) is applied to that set.
  The harness is `examples/voice_eval.rs`; audio stays in
  `~/meetingai-eval/`, never in git.
