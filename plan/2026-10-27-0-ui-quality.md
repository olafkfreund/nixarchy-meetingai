# Plan: a UI that is easy to use and looks native to Omarchy

## Approved decisions (copied from the spec)

- **One control metric:** `shell/Theme.qml` (plugin singleton) exposes
  `ctl = round(Style.spacing.controlHeight × ts)`, `gap =
  Style.spacing.controlGap × ts`, `padX`, `padY`, `radius`, `section` and
  font sizes. Every form row is a `RowLayout` with
  `Layout.preferredHeight: Theme.ctl`, each child `Qt.AlignVCenter`,
  fields `fillWidth`, buttons the same height. No fixed pixel widths that
  can clip text. IconButton has the same height with or without an icon.
- **Font:** `Style.font.family` everywhere (bubbles, answers, inputs,
  labels); sizes from `Style.font.*` × `ts`.
- **Mode picker:** names *Assist · Interview me · Team · Interview
  someone* with one-line descriptions; values stay `general | interview |
  team_meeting | interviewer`. Compact: the header shows the current
  name and opens a list. Keyboard-navigable (`Ui.ButtonGroup` inside the
  list, or the list itself focusable).
- **Candidate tab:** sections (Candidate / Documents / Question bank /
  Danger zone) with `Ui.PanelSectionHeader`; "New…" opens an inline name
  row with Create/Cancel; one document row per file plus "Attach CV…" /
  "Attach job description…" that open a path row; one card per question
  (text full width and wrapping, source quote on its own wrapped line,
  footer with competency tag and up/down/delete aligned right); Generate
  with a progress state and the dropped note; Danger zone delete via
  `Ui.ConfirmDialog` naming everything removed; read-only banner for
  past candidates.
- **Keyboard and a11y:** `focusable: true` on every button; the composer
  gets focus on open; suggestion rows are focusable buttons (Enter sends,
  1/2/3 keep working); Escape closes dialog → drawer → edit → overlay;
  `Accessible.name`/`role` on every control.
- **Confirm** delete session, delete profile, delete candidate, and the
  bar's "Stop Meeting AI…" (was "Quit").
- **First run:** the daemon's `state` gains `ready: {chat, speech}` and
  `hints: {chat, speech}`; a Setup card shows one next step each
  (daemon down → "Start the service" running `systemctl --user start
  nixarchy-meetingai` plus the command to copy; no provider → opens
  Providers; speech down → the unit to check).
- **Errors in place:** failed answer inside NOW with Retry; Library
  failures under their section; the header line only for connection loss.
  "Writing…" waiting bar between `answer.started` and the first delta.
- **Hierarchy:** NOW body = `Style.font.body × 1.15 × ts`, solid accent
  rule, metadata on one caption line; bubbles smaller and lighter;
  archived answers collapse to two lines with "Show"; empty transcript is
  one line; empty question bank shows "Prepare candidate".
- **Shell contract:** outer card and consent callout use
  `Ui.BorderSurface` with the theme border spec.
- **Client robustness:** on disconnect only function callbacks are called
  and session state is cleared; on reconnect `history` replaces the
  transcript.
- **Structure:** split `Overlay.qml` into `Header.qml`, `Transcript.qml`,
  `NowCard.qml`, `ItemsPanel.qml`, `QuestionBankPanel.qml`,
  `ConsentBanner.qml`, `SetupCard.qml`; Overlay keeps window, geometry,
  layout.

## Repo traps

- Shell tests run as `devenv shell -- env -u SIZE bash shell/tests/<x>.sh`
  (devenv exports `SIZE`).
- The screenshot harness draws on the owner's real desktop. Look at every
  crop; retake any crop covered by another window; never keep
  full-desktop screenshots.
- Omarchy components live in
  `/nix/store/*-nixarchy-omarchy-tree/shell/Ui` (read their properties:
  `Ui.Button.focusable` defaults to false; `ToggleSwitch.checked` changes
  only when the caller sets it). Tokens are `Style.spacing.*`,
  `Style.font.*`, `Commons.Color.*`.
- QML bindings read inside a change handler of a property they depend on
  can be stale (we hit this in `Client.qml`); compute from sources.
- Coders cannot commit; the lead commits each step.
- cargo only via `devenv shell -- <cmd>`; rustfmt only touched files.

## Steps

1. **Split `Overlay.qml`** into the seven files, with no visual or
   behaviour change. Update `manifest.json` only if it lists files.
   → verify by lint, smoke, smoke-real, and crops of every scenario
   pixel-compared to the previous ones (same within anti-aliasing).
2. **Theme.qml + alignment:** add `shell/Theme.qml` (and its `qmldir`
   entry); convert every form row in Overlay parts, Library and Composer
   to the row rule; IconButton fixed height; font family everywhere.
   Add `shell/tests/geometry.js`: under the harness, log `objectName`,
   `x/y/height` of every control and every text's `implicitWidth` vs
   `width`; `shell/tests/check-geometry.py` fails on a row whose controls
   differ by more than 1 px in top or bottom, or on clipped text.
   → verify by `check-geometry.py` on all scenarios at 100 % and 150 %.
3. **Candidate tab** rebuilt as above, with `Ui.ConfirmDialog`.
   → verify by geometry check and interviewer crops at 100 % and 150 %.
4. **Mode picker, keyboard and a11y:** compact picker with the new names
   and descriptions; `focusable` everywhere; composer focus on open;
   suggestion buttons; Escape order; Accessible names. Add
   `shell/tests/keys.sh`: drives Tab through header and Candidate tab via
   the harness and asserts `activeFocusItem.objectName` changes.
   → verify by `keys.sh` and crops.
5. **Confirmations** for session, profile and daemon stop.
   → verify by smoke (the dialogs open in a harness scenario).
6. **First run and errors:** daemon `state.ready`/`hints` in
   `src/daemon/session.rs` (`state_value`, computed from `chat_config`
   and `speech_config`) with a unit test; `SetupCard.qml`; in-place
   errors with Retry; the waiting bar; `fake-daemon.py --first-run`
   (no provider) and a "no daemon" harness case.
   → verify by `cargo test --workspace`, clippy, and `first-run` crops.
7. **Hierarchy and shell contract:** NOW sizes and rule, quieter bubbles,
   collapsing archived answers, one-line empty transcript, "Prepare
   candidate", `Ui.BorderSurface` for the card and consent callout.
   → verify by crops of every scenario, contrast.py, geometry check.
7a. **Recording indicator (owner request, 2026-10-27):** while recording,
   the header's record button and the bar widget show a **red** dot with a
   gentle pulse (the one colour exception to monochrome), plus the timer;
   paused or finishing shows the dot steady. The red comes from the theme
   (`Commons.Color` red/urgent token if present, else `#e5484d`) and must
   pass 3:1 against the header in light and dark themes (add a row to
   `contrast.py`). The pulse respects reduced motion.
   → verify by crops while recording in light and dark themes, contrast.py.
8. **Client robustness:** disconnect/reconnect handling in `Client.qml`;
   fake daemon `--drop` that closes the socket mid-answer and reconnects.
   → verify by smoke with `--drop` (no QML errors in `qs.err`, no
   duplicated rows).
9. **Review:** a fresh Opus review with this path and `git diff`, then
   Codex and agy (screenshots attached), read-only; fix confirmed
   findings; owner sign-off on the final crops.

## Tests

- `check-geometry.py` passes for every scenario at 100 % and 150 %.
- `keys.sh`, lint, smoke, smoke-real, contrast pass.
- `devenv shell -- cargo test --workspace --no-fail-fast` and clippy
  `-D warnings` pass (step 6 touches the daemon).
- `git add -A && nix flake check` passes.

## Rollback

Each step is its own commit; `git revert` any of them. Step 1 is a pure
move, so later steps can be reverted independently. The daemon change in
step 6 adds fields only.

## Implementation split

One `coder` does steps 1–8 in order (they all touch the same QML), with
the lead committing after each step and looking at the crops between
steps. Step 6's daemon part is small and stays with the same coder.

## Deviations log (recorded with the implementation commit)

None yet.
- **Step 1:** the Items card hosts the question bank (`ItemsPanel.qml`
  wraps `QuestionBankPanel.qml`); the Client id in Overlay is `backend`
  (qmllint `id-shadows-member` with a `daemon` property);
  `lastOpen`/`lastTime`/`transcriptOpen` stay in Overlay for the harness.
  An existing "binding loop for height" warning on the transcript list
  is carried over and fixed in step 2.
- **Step 2:** `Theme.qml` is a plain `QtObject` created once in Overlay
  and passed down as `theme` (no plugin-folder singleton exists in the
  omarchy tree, and the harness symlinks only `*.qml`). New helpers
  `UiText.qml`, `Input.qml`, `Cell.qml`. The geometry check also fails on
  controls not exactly `ctl` tall and on anything outside the card; the
  r5 harness visits Restore, Providers and Settings too. The profile list
  column is 38 % wide (was 28 %). The transcript binding loop is fixed by
  reading `contentHeight` one tick late.
- **Step 3:** `Ui.Dropdown`/`SearchableDropdown` hard-code `Style.font.body`
  with no size input, so a new `shell/Select.qml` (same trigger, popup,
  keys, optional search) replaces every dropdown at `theme.body`/`ctl`;
  the geometry check fails on mixed font sizes in a row and on any
  `Ui.Dropdown`. The Candidate tab lives in `shell/CandidateTab.qml`.
  `Ui.ConfirmDialog` has no text-size input (small at 150 %) and covers
  the tab, not the whole card. Labels: "New…", "Attach CV…", "Attach job
  description…", "Delete candidate…".
- **Step 4:** our own `Confirm.qml` (whole card, `theme.body`, Cancel
  focused first) replaces `Ui.ConfirmDialog`, called through
  `overlay.ask()`. `ModePicker.qml` replaces the segmented control; the
  header hides the profile name when it doesn't fit. `keys.sh` walks the
  focus chain with `nextItemInFocusChain` (no key injection available), so
  it proves reachability, not physical Tab delivery. `Ui.ToggleSwitch` has
  no focus support, so toggles have accessible names but aren't Tab
  stops. The profile in use shows "● name". The geometry check also fails
  on controls without an accessible name.
- **Steps 5–6:** the tab bar is a `Flow` (wraps at 520 px / 150 %);
  `Check.qml` makes toggles Tab stops. The bar popup keeps its own
  `Ui.ConfirmDialog` for "Stop Meeting AI…" (the overlay's dialog can't
  reach a separate popup). `state_value` became a method returning
  `ready`/`hints` (null hint = ready). `lastError` is gone from the client:
  errors show per section; the header line is connection loss only. New
  fake-daemon flags `--first-run`/`--error` and shot scenarios
  `first-run`, `no-daemon`, `error`.
